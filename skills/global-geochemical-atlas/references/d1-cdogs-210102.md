# CDoGS survey 210102 lake sediment and lake water

This D1 adapter adds two executable media from one traceable upstream survey:

| D1 source ID | Medium | Official survey rows | Published observations |
|---|---|---:|---:|
| `cdogs-210102-lake-sediment` | lake sediment | 655 in package 0134; 481 in package 0383 | 4,411 |
| `cdogs-210102-lake-water` | lake water | 655 in package 0136 | 655 |

Both source IDs share `upstream_lineage_id=cdogs-survey-210102`. They expand
medium coverage but count as one independent survey lineage. The authoritative
survey is [CDoGS 210102](https://geochem.nrcan.gc.ca/cdogs/content/svy_ext/svy210102_e.ext.htm),
National Geochemical Reconnaissance lake-sediment and lake-water sampling in
part of NTS 031C, Ontario.

## Why this survey

The initially considered Nova Scotia 1983 survey (`svy040022`) has a discovery
page but no stable standardized Extended Metadata workbook exposed through the
same CDoGS interface. Survey 210102 was selected because its numeric files,
survey key, coordinates, packages, methods, laboratories, detection limits,
and publication lineage can all be resolved through official CDoGS records.
The Nova Scotia item remains a discovery candidate rather than being presented
as executable data.

## Fixed official files and identity

The adapter consumes the `c` workbook variants, because CDoGS documents that
these preserve source values such as `<2` as text.

| File ID | Official file | Observed bytes | Survey rows after exact filter | Method/package role |
|---|---|---:|---:|---|
| `pkg-0134c` | `svy210102_pkg_0134c.xlsx` | 3,447,178 | 655 | sediment Zn, Cu, Pb, Ni, Hg, As |
| `pkg-0383c` | `svy210102_pkg_0383c.xlsx` | 568,509 | 481 | sediment Cr |
| `pkg-0136c` | `svy210102_pkg_0136c.xlsx` | 563,410 | 655 | water U |

CDoGS standardized package workbooks contain rows from more than one survey.
The adapter therefore requires and exactly filters `Survey_Key=21:0102`.
Workbook byte counts are drift evidence, not cryptographic identity. No
MD5/SHA value is calculated, consumed, or updated.

The source identity record also retains the official URL, file ID/name,
dataset version, XLSX member/header structure, selected row count, method
column counts, and source statistics. A workbook with no matching survey rows
or no values in a required method column fails explicitly.

## Method and value semantics

Methods are assigned only through the official package-column method tables;
they are not inferred from analyte or unit. The preserved methods are:

- sediment package 0134: methods 2091–2094 (flame AAS), 2118 (cold-vapour
  AAS), and 2117 (colorimetry), with the package-native digestion and Chemex
  laboratory;
- sediment package 0383: method 1088, LiBO2 fusion XRF, X-Ray Assay
  Laboratories;
- water package 0136: method 1999, fission-track uranium, Bondar Clegg.

Every emitted measurement keeps `value_raw`, a separate parsed numeric value,
the source qualifier, source unit, package detection limit, method ID,
laboratory, and row/column locator. `<DL`, `rejected`, and literal `missing`
states remain distinct. D1 does not replace censored values, convert units, or
interpret anomalies.

## Samples, coordinates, and time

The full survey description reports 617 lake-sediment and 617 lake-water
samples. The standardized package files include reanalysis and QA/QC-related
field rows, which explains the larger 655/481 package row counts. The profile
therefore reports both unique field sample IDs and unique site IDs rather than
silently forcing the workbook rows to equal the narrative sample count.

Coordinates are source-native `Latitude_NAD83` and `Longitude_NAD83`, recorded
as `EPSG:4269`. They are not relabelled as WGS84. A later D1 coordinate stage
may transform them while retaining these source fields.

The survey narrative says lake water was collected in 1982, while package and
bundle metadata encode 1976. The adapter does not choose one: water
`sampled_year_raw` remains null and `sampling_time_note` records the conflict.
Lake sediment retains the survey-reported 1976 collection year; analysis years
remain package-specific.

## Publication and access lineage

- package 0134 observations retain Geological Survey of Canada Open File 405;
- packages 0383 and 0136 retain Geological Survey of Canada Open File 899;
- all rows retain the CDoGS survey URL, workbook URL, package method page, and
  precise source row/column.

The files are available by public Government of Canada download. The adapter
records the [Government of Canada website terms](https://www.canada.ca/en/transparency/terms.html)
and `public_research_use`; redistribution is deliberately marked not assessed
because redistribution is not required for this research workflow.

## Reproduction and audit

Run against the official files or an existing cache:

```bash
python3 scripts/cdogs_210102_adapter.py \
  --cache-dir /path/to/cdogs-cache \
  --output-dir /path/to/output

python3 scripts/cdogs_210102_adapter.py \
  --cache-dir /path/to/cdogs-cache \
  --output-dir /path/to/output \
  --offline
```

Tracked fixtures contain source-native raw rows, their complete replayed
observations, a full-population profile, run manifest, and 30 structured Codex
audit decisions per source ID. The fixture is intentionally small; the profile
was generated from all exact-matching rows and no production sample cap exists.

## Claim boundaries

- This is one Ontario survey, not Canadian or global uniform coverage.
- The two media are separate queryable source IDs but one upstream lineage.
- Lake water currently contains package-native U, not the seven earlier target
  elements; it is still a valid independent lake-water source and the schema
  accepts other analytes.
- QA/QC and reanalysis rows are preserved and identifiable, not treated as
  additional independently sampled sites.
- Original NAD83 coordinates and the unresolved water sampling year must remain
  visible to downstream consumers.
