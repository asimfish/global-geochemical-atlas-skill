# D1 数据源准入标准

版本：`geochemical-source-acceptance-v1`  
核对日期：2026-08-05

## 目的

本标准决定一个已发现的数据源能否被 D1 自动用于生产。进入 `source_catalog.json` 只表示“已经发现并值得跟踪”，不表示数值可靠，也不表示允许下载或再分发。

生产来源必须通过全部硬门；任一硬门失效时，来源自动退出生产路由，进入 `needs_human_review` 或更严格状态。

## 状态

| 状态 | 自动用于生产 | 使用原则 |
|---|---:|---|
| `approved` | 是 | 所有硬门通过，适配器与固定版本已经验收 |
| `conditional` | 条件满足时 | 条件必须机器可判定，例如记录级许可或明确区域范围 |
| `metadata_only` | 否 | 只用于发现上游数据、引用或描述覆盖 |
| `needs_human_review` | 否 | 版本、许可、接口、字段、完整性或适配器仍需复核 |
| `rejected` | 否 | 来源不明、访问违规、许可不允许或无法建立证据链 |

## 十项准入门

| 门 | `approved` 的最低要求 |
|---|---|
| identity | 发布者、数据集标题、官方落地页和官方证据 URL 明确 |
| version | 固定版本、发布日期或不可变 DOI；动态服务必须生成可复现快照 |
| license | 许可 ID、条款 URL、署名和再分发要求明确，符合 `open_only` |
| interface | 使用明确 HTTPS API 或文件端点；分页、过滤、限制和错误行为可测试 |
| provenance | 能回到数据集、原文件、原始记录和原始出版物 |
| schema | 样品、坐标、介质、分析物、值、单位和关键方法字段可以解释 |
| integrity | 文件或归档成员有发布方 checksum，或清楚标注的本项目观测 hash 与完整文件清单 |
| adapter | 适配器只解析来源事实，固定版本可重复运行，失败时关闭而不是猜测 |
| registry alignment | 候选目录、生产注册表和适配器的版本、许可、DOI 完全一致 |
| limitations | 聚合、选择值、缺失方法、坐标精度、覆盖偏差和许可限制明确记录 |

## 准确性复核

每个新来源在批准前必须完成：

1. 原始总数与解析成功、明确拒绝和失败记录对账；
2. 至少 30 条分层人工回看，不足 30 条时全量回看；
3. 抽样覆盖正常、缺失、删失、重复和边界值；
4. 单位、坐标和日期转换有已知答案或往返测试；
5. 任意观测记录可以回到原始文件、sheet/行/列或 API 记录；
6. 来源更新或字段映射变化时，旧批准自动失效并重新审计；
7. 跨来源冲突保留双方原值、方法、版本和证据，不做无依据平均。

30 条人工回看是字段映射的最低抽查，不取代全量 schema、hash、分页、记录数和关系完整性检查。

## 许可与访问红线

- 不绕过登录、联系表单、下载上限或访问控制；
- mixed、non-commercial、limited 或 restricted 记录不能混入 open-only 产物；
- 聚合平台的许可不能覆盖上游数据提供者的独立条款；
- MIT 只覆盖本仓库原创代码和文档，不覆盖第三方数据；
- 许可不清时保留元数据和发现证据，不下载或再分发原始数值。

## 审计命令

```bash
python scripts/source_audit.py --output source_audit.json
```

审计输出的 `PASS` 只说明来源元数据、固定版本、获取契约和证据链内部一致，不等于证明每个历史测量值是真值。单条记录的科学可比性和 operational confidence 仍由 D2 负责。
