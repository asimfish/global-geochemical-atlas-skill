## 一句话说明

把项目的全部数据入口管起来：知道去哪里查、知道为什么可信、知道覆盖到什么程度，用统一结构保存，并能快速、稳定地把数据和来源证明交给后续分析与制图。

这不是“尽量多下载数据”，而是建设一个有目录、有准入、有覆盖说明、有缓存和稳定交付格式的数据供应系统。

## 一、把任务拆成五个问题

| 问题 | 朴素解释 | V2 要给出的答案 |
|---|---|---|
| 1. 去哪里查，接口是什么 | 哪些数据库、API、下载页和论文附件值得看，怎么访问 | 数据源目录、接口卡片、统一查询入口 |
| 2. 数据是否可信 | 谁发布、版本是什么、能否追溯、许可是否明确 | 数据源准入规则、可信状态和证据记录 |
| 3. 数据是否全面 | 覆盖哪些地区、介质、元素、年代和方法，还有哪些空白 | 覆盖矩阵、缺口报告和补源优先级 |
| 4. 数据如何统一结构 | 不同数据库字段各不相同，怎样表达同一个样品、测定和方法 | 分层 data schema、字段字典、映射规则和查询视图 |
| 5. 是否够快，存成什么 | 不重复下载，断网可用，后续工具拿到就能处理 | 过滤、缓存、索引、稳定交付格式和性能记录 |

## 二、最终工作方式

```text
用户的数据需求
  │ 地区、介质、元素、时间、开放许可要求
  ▼
数据源目录与路由
  │ 告诉系统去哪里查，接口和限制是什么
  ▼
可信准入门
  │ 发布者、版本、许可、来源链、字段和校验规则
  ▼
下载 / API 查询 / 缓存
  │ 尽量服务端过滤；本地验证、缓存和索引
  ▼
统一归档 schema
  │ 数据集 → 采样 → 样品 → 测定 → 方法，并保留原始值
  ▼
D1 稳定交付
  ├─ 分层归档包与原始观测长表
  ├─ 每条记录的来源证明
  └─ 本次运行清单和覆盖缺口
  ▼
D2 科学标准化与分析 → D3 地图与最终 Skill
```

成功标准不是“下载到了一个大文件”，而是后续工具能够明确知道：哪些数据可以用、为什么可以用、哪些地方没有数据，以及如何复现本次获取结果。

### 最高优先级：完整和准确优先

本项目把数据供应质量视为后续推测、制图和比赛结论的基础。实施顺序固定为：

1. 先确认信源是否覆盖需求；
2. 再确认来源、版本、字段、方法和记录是否可信；
3. 再做结构化、缓存和性能优化；
4. 最后才扩大数据量和展示范围。

如果完整性或准确性门槛未通过，系统必须返回 `partial`、`uncovered`、`unknown` 或失败状态，不能为了产出地图或满足记录数而静默补值、猜字段、混用方法或扩大结论。

这里的“确保”指建立可审计的质量保障链，而不是承诺无法验证的绝对真值。历史测量是否代表真实地质状态，最终仍受采样设计、实验方法和原始研究质量限制；D1 必须把这些限制完整交给 D2，而不能用一个来源等级掩盖。

### 六道质量门

| 质量门 | 必须回答的问题 | 未通过时的行为 |
|---|---|---|
| 覆盖门 | 请求的地区、介质、元素、时间和方法是否有批准来源覆盖 | 标记缺口，不生成“已全面覆盖”的结论 |
| 来源门 | 是否为可确认的官方机构、可信仓库或原始研究，版本和许可是否明确 | 不进入生产批准清单 |
| 语义门 | 样品、介质、分析物、单位、测量基准和方法含义是否可以解释 | 保留原文并待复核，不猜测映射 |
| 完整性门 | 文件是否完整，分页是否截断，记录数、hash 和必需字段是否符合预期 | 本次获取失败或降级，不静默使用残缺数据 |
| 追溯门 | 每条测定能否回到数据集版本、原文件、行列和引用 | 该记录不得进入正式交付 |
| 复现与复核门 | 相同版本和请求能否重现；抽样记录能否与官方原始记录一致 | 阻止发布并输出差异报告 |

跨来源比较用于发现数量级、单位、空间位置和方法差异，但不能把“多个来源写得一样”直接当作真实值证明。发生冲突时保留各自原值、方法和证据，不做无依据的平均或择一。

## 三、范围边界

### D1 V2 负责

- 维护数据源和文献元数据入口目录；
- 记录 API、批量下载、分页、过滤、速率限制和认证要求；
- 建立数据源准入规则并保留证明材料；
- 描述地区、介质、元素、时间和方法元数据覆盖；
- 维护 D1 归档 schema、字段字典、受控词汇引用和来源字段映射；
- 下载、缓存、校验、索引和增量更新；
- 保留数据集 DOI、原始文献、许可、版本、文件和记录定位；
- 向 D2 提供来源原值、原单位和原始方法字段；
- 向 D3 提供稳定运行状态、数据清单和覆盖缺口；
- 输出“数据来源与置信度说明”所需的来源证据。

### D1 V2 不负责

- 不判断某个元素值是否异常；
- 不制定最终单位换算和科学质控规则；
- 不把来源可信等级当作单条测量值的准确率；
- 不根据地图结果解释污染、矿床或成因；
- 不负责最终交互地图表现和最终 `SKILL.md`；
- 不覆盖来源原值；D1 的可逆解析字段与 D2 的科学标准化字段必须分开；
- 不批量抓取付费全文，不绕过登录、表单或访问限制；
- V2 不做 PDF 数值表格和扫描件 OCR 自动入库。

## 四、工作流 A：去哪里查，接口是什么

### A1. 建立“候选目录”和“批准清单”两层结构

候选目录回答“可能去哪里查”，批准清单回答“当前生产流程允许自动使用什么”。两者不能混在一起。

- `assets/source_catalog.json`：广泛记录候选数据库、文献元数据服务和访问能力；
- `assets/source_manifest.json`：只保留已经完成版本、许可、字段和校验验证的生产来源；
- 默认运行只使用批准清单；候选目录只用于发现和缺口分析。

### A2. 每个来源建立接口卡片

最低记录以下内容：

- 来源名称、发布者、主页和 DOI；
- 数据介质、地区、元素、年代和大致记录规模；
- 元数据接口、查询接口、下载接口；
- 支持的服务端过滤条件；
- 返回格式和 schema/version；
- 分页、最大记录数、速率限制和超时行为；
- 是否需要账号、人工表单或 API key；
- 更新频率和版本发现方式；
- 官方引用和原始论文定位方式；
- 许可、再分发和署名要求；
- 当前适配器和验证状态。

### A3. 建立统一查询请求

建议 D1 接收以下请求字段：

```json
{
  "region_bbox": [73, 18, 135, 54],
  "media": ["rock", "soil"],
  "analytes": ["As", "Cu", "Ni", "Zn"],
  "time_range": null,
  "open_only": true,
  "max_records": 50000,
  "mode": "online"
}
```

路由结果必须说明：

- 选择了哪些批准来源；
- 为什么选择；
- 哪些条件被满足；
- 哪些条件只有部分覆盖；
- 哪些需求没有合适来源；
- 实际使用的接口和过滤参数。

### A4. 文献元数据的定位

- D1 保存数据集对应论文、DOI 和标准引用；
- 可以通过 DataCite、Crossref 或 OpenAlex 等接口补充公开文献元数据，但需要单独完成来源准入；
- 文献摘要只用于发现和说明，数值仍必须回到可追溯的数据文件或补充材料；
- 没有开放全文时只保存元数据，不把摘要推断成数据事实。

## 五、工作流 B：数据是否可信

### B1. 可信不是一个模糊分数，而是一组硬条件

生产来源必须同时回答：

1. 谁发布：官方机构、研究数据仓库或可确认的原始研究团队；
2. 哪个版本：有版本号、发布日期或不可变 DOI；
3. 如何追溯：能定位到原始文件、原始记录和原始引用；
4. 是否可用：许可和署名要求明确；
5. 文件是否完整：有发布方 checksum，或明确标注本项目观测 hash；
6. 字段是否可解释：样品、坐标、介质、单位和方法字典不缺失；
7. 获取是否稳定：接口、分页和错误行为可以测试；
8. 限制是否明确：选择值、聚合、缺失字段和方法差异不被隐藏。

任何硬条件不满足时，不得静默进入生产批准清单。

### B2. 来源状态

| 状态 | 含义 | 是否自动用于生产 |
|---|---|---|
| `approved` | 版本、许可、来源链、字段和校验全部通过 | 是 |
| `conditional` | 来源可信，但只适用于特定地区、介质、字段或许可条件 | 满足条件时使用 |
| `metadata_only` | 只能保留 DOI、引用或发现信息，不能可靠取得数值 | 否 |
| `needs_human_review` | 许可、字段、方法或版本仍需人工确认 | 否 |
| `rejected` | 来源不明、无法追溯、访问违规或内容不完整 | 否 |

### B3. 来源可信与记录质量分开

- D1 给出来源层面的发布者、版本、证据完整性、许可和可复现性事实；
- D2 决定单条记录的方法可比性、单位处理、QC 和置信度算法；
- 权威数据库中的记录也可能因方法缺失或采样差异而不能直接比较；
- D1 不输出“这个数值有 90% 概率正确”之类没有依据的结论。

### B4. 每个来源和适配器的准确性复核

每个生产来源必须完成以下复核，不能只验证脚本“能跑完”：

- 原始文件总数、行数或 API 分页总数，与解析成功、明确拒绝和失败记录对账，不能有原因不明的记录消失；
- 对分析物、值、单位、限定符、坐标、样品 ID、方法和来源定位做分层抽样回看；每个来源至少覆盖正常值、缺失值、删失值、重复值和边界值；
- 首版每个来源至少人工核对 30 条记录，或在不足 30 条时全量核对，并保存核对记录；
- 对所有单位和坐标转换做固定 fixture、往返或已知答案测试；
- 来源发布新版本或适配器字段映射变化时，原批准状态自动失效，必须重新复核差异；
- 发现来源冲突时生成 conflict report，保留各方原值、方法、版本和证据，不静默覆盖。

“30 条人工核对”只是适配器字段映射的最低抽查，不代表只检查 30 条数据。全量 schema、hash、记录数、分页、必需字段和关系完整性检查仍由程序执行。

## 六、工作流 C：数据是否全面

### C1. “全面”的定义

全面不等于把所有能找到的数据放在一起。V2 将全面定义为：系统能清楚描述当前覆盖和空白，并按缺口选择下一批数据源。

覆盖至少按以下维度统计：

- 地区：国家、洲、全球范围或 bbox；
- 介质：rock、soil、sediment、water；
- 元素：可用分析物和单位表达；
- 时间：采样时间和数据版本时间；
- 空间密度：站点数、坐标率和明显空洞；
- 方法元数据：分析方法、消解/提取方法、实验室；
- 来源链：原始提供者、聚合平台和文献引用完整度；
- 开放性：可自动下载、需人工申请、仅元数据。

每个需求返回：`covered`、`partial`、`uncovered` 或 `unknown`，禁止把未知写成已覆盖。

### C2. 当前覆盖判断

| 介质 | 当前批准来源 | 当前判断 | 主要缺口 |
|---|---|---|---|
| 岩石 | GEOROC Archaean Cratons v12.0 | `partial` | 只覆盖太古宙克拉通，不能代表全部全球岩石 |
| 土壤 | USGS Data Series 801 | `partial` | 只覆盖美国本土，不能代表全球土壤 |
| 水体 | 无 | `uncovered` | 需要公开、可批量取得且许可清晰的水化学来源 |
| 沉积物 | 无 | `uncovered` | 需要可追溯的区域或全球沉积物来源 |

候选方向可以包括 EarthChem/PetDB、GEMAS/WoSIS、GEMStat 和各国官方发布，但进入生产前必须逐一通过 B 工作流。候选名称不等于已经批准使用。

### C3. 全介质信源范围

岩石、土壤、沉积物和水体全部属于正式建设范围，不做介质取舍。每类介质都要覆盖以下信源层次：

1. 全球性或学科性数据库与数据门户；
2. 国际组织、国际合作计划和区域性地球化学计划；
3. 各国地质调查、自然资源、环境、水文和科研机构的官方数据；
4. 大学、研究所和可信领域仓库发布的带 DOI 数据集；
5. 原始论文关联的开放补充数据和数据论文；
6. 聚合平台所引用但未完整收录的上游原始数据集。

`source_catalog.json` 尽可能收录所有发现的相关信源，包括暂时只能查看元数据、需要人工申请、许可待确认或接口尚未适配的来源；`source_manifest.json` 仍然只包含通过质量门、当前可用于生产的来源。这样既不会因为暂时不能下载而遗漏信源，也不会为了追求数量把未验证数据放进正式结果。

### C4. 补源顺序只决定先后，不缩减范围

建议使用以下接入顺序，而不是按知名度选择。完成前面的来源不代表后面的来源可以不做：

1. 先补当前完全空白的介质；
2. 再补当前只有单一区域的全球覆盖缺口；
3. 再补关键元素或方法字段缺失；
4. 最后才增加重复覆盖较高的数据源；
5. 同等覆盖收益下，优先开放、结构化、可版本化和可服务端过滤的来源。

### C5. 怎样证明信源找得足够全

“足够全”按目标需求的覆盖范围验收，不使用“已经搜过很多网站”作为证明。

- 建立 `source_discovery_log.jsonl`，记录搜索渠道、关键词、时间、发现结果、重复来源、纳入/排除理由和最后复核时间；
- 对每种目标介质同时检查全球/学科数据库、国际项目、目标地区官方地调或环境机构、研究数据仓库与论文关联数据；
- 对每个 `地区 × 介质 × 分析物 × 时间` 单元给出 `covered / partial / uncovered / unknown` 和支持它的来源列表；
- 关键覆盖单元在存在独立来源时至少比较两个来源；只有一个来源时明确标记 `single_source_dependency`；
- 识别聚合库与原始提供者关系，避免把同一批数据在多个平台出现误算成独立证据；
- 对未覆盖单元至少通过两个独立发现渠道复核后才能标为 `uncovered`；只查过一个渠道时仍为 `unknown`；
- 新发现来源必须先进入候选目录并经过准入，不以补覆盖为理由降低可信门槛。

信源普查按版本和核对日期发布。只有连续两轮独立发现复核都没有新增高相关来源，并且全球、区域、国家、领域仓库和论文关联数据渠道都已经检查，才可以把当前版本标记为“发现趋于饱和”。这仍然表示“截至核对日期、在可检索范围内尽可能完整”，不表示世界上永远不会再出现新数据源。

覆盖矩阵既报告记录数量，也报告空间分布、来源独立性、方法元数据完整度和许可可用性。只有记录很多但集中在少数国家或来自同一上游数据集，仍然只能算 `partial`。

## 七、工作流 D：数据如何统一成可查询、可归档的 schema

### D-1. 先确定结构原则

不采用“一张不断加列的大宽表”作为长期归档模型。一个样品可能有几十个元素、多个分析方法、重复测定和子样品；把所有信息塞进一行或在每个元素行重复样品与来源信息，都会造成更新冲突和证据链不一致。

V2 采用“分层归档、长表交换、索引派生”的结构：

```text
数据集 / 来源 ── 出版物与许可
      │
      └── 采样事件 / 地点
                 │
                 └── 样品 ── 父样 / 子样关系
                        │
                        └── 测定 observation ── 分析方法
                                  │
                                  └── 原始记录定位与处理证据

规范化归档表 ──生成──> D1 → D2 观测长表
       │
       └────生成──> SQLite 查询索引和覆盖统计
```

- **原始层**：发布方原文件和响应保持不变，以 hash 和版本固定；
- **归档层**：按数据集、采样、样品、测定、方法和证据拆分实体；
- **交换层**：为 D2 生成“一行一个分析物测定”的扁平长表，便于脚本处理；
- **索引层**：从归档层生成 SQLite 索引和查询视图，可以随时重建，不是唯一事实来源。

现有 `geochemistry-record.schema.json` 继续作为 **D2 标准化测定结果**，不直接承担 D1 数据集、样品关系和采集运行的完整归档。V2 新增的 D1 schema 与它建立显式字段映射，不替换它。

### D-2. 核心实体与重要参数

| 实体 | 回答的问题 | 核心参数 |
|---|---|---|
| 数据集与来源 `dataset_source` | 数据从哪里来，哪个版本，能否使用 | `source_id`、`dataset_id`、`dataset_doi`、`dataset_version`、发布者、URL、许可、引用、获取时间、文件 hash |
| 出版物 `publication` | 数据对应哪篇论文或报告 | DOI、标准引用、标题、作者、年份、与数据集/样品的关系 |
| 采样事件与地点 `sampling_event` | 在何时、何地、怎样取得样品 | `event_id`、`site_id`、采样时间、采集方法、经纬度原值、CRS、标准坐标、坐标不确定度、海拔、深度范围、地点描述 |
| 样品 `sample` | 被测的物理对象是什么 | `sample_id`、来源原始 ID、IGSN、父样 ID、介质、材料/岩性、地质单元、土层、粒级、过滤状态、样品描述 |
| 测定 `observation` | 哪个样品的什么参数测得多少 | `observation_id`、`sample_id`、分析物原名、原始值、数值解析、限定符、原始单位、测量基准、检出限、不确定度、重复编号、`method_id` |
| 分析方法 `analytical_method` | 这个值是怎么测出来的 | 前处理、消解/提取、分析技术、仪器、实验室、校准、标准物质、空白、精密度/准确度说明、方法引用 |
| 来源定位与处理 `provenance` | 如何回到原始证据并复现转换 | 文件/接口、sheet、行、列、来源记录 ID、输入 hash、适配器版本、处理步骤、输出 hash |
| 获取运行 `acquisition_run` | 这次任务实际做了什么 | `run_id`、请求、来源选择、schema 版本、词汇版本、开始/结束时间、数量、耗时、缓存状态、成功/降级/失败状态 |

第一版字段按必要性分三级：

- **P0 必须有或必须说明为什么没有**：稳定 ID、来源/版本、原始记录定位、样品 ID、介质、分析物、原始值、原始单位、位置、许可、输入 hash；
- **P1 强烈建议**：采样时间、深度、方法、消解/提取、实验室、检出限、测量基准、坐标不确定度、IGSN；
- **P2 专业扩展**：岩性、地质年代、土层、粒级、水样过滤状态、标准物质、重复测定、仪器校准、子样关系等。

来源没有 P1/P2 字段时允许入库，但必须保留明确的缺失原因并进入 completeness 统计；P0 缺失是否允许生产使用，由来源准入规则决定，不能由适配器静默猜测。

### D-3. D1 原始事实与 D2 科学标准化的边界

| 内容 | D1 可以做 | D2 负责 |
|---|---|---|
| 数值 | 保存 `value_raw`，可逆解析为数值和限定符 | 单位换算、删失值策略、可比性判断 |
| 分析物 | 保存 `analyte_reported` | 统一元素/氧化物/同位素名称和语义 |
| 单位 | 保存 `unit_raw` | 映射标准单位并记录换算公式 |
| 介质/岩性 | 保存来源术语和词汇映射候选 | 决定最终科学分类及是否可合并 |
| 坐标 | 保存原值和 CRS；仅做可复现的坐标解析/转换 | 空间 QC、适用性和异常判断 |
| 方法 | 保存来源原文、方法代码和链接 | 方法可比性、质量门控和置信度分量 |
| 质量 | 报告来源证据和字段完整性事实 | 记录 QC、异常规则和 operational confidence |

规则是：任何标准化值都不能覆盖 `*_raw`；转换后字段必须记录转换规则和版本。无法确定时保留 `null` 和原因，不用看似合理的默认值补齐。

### D-4. schema 的共同规则

- 所有实体使用稳定 ID；来源提供永久 ID 时优先使用，样品支持 IGSN；没有永久 ID 时按有文档的 canonical 字段生成稳定 hash ID；
- 样品父子关系单独表达，不能把母样和粉末、切片、溶液等子样当成同一对象；
- 时间采用 ISO 8601，保留来源原文；系统运行时间统一 UTC，采样时间保留来源时区或不确定性；
- 位置同时保存来源坐标、来源 CRS、WGS84 查询坐标和坐标不确定度；不能把小数位数直接等同于真实精度；
- 分析值必须同时表达值、单位、限定符和测量基准；`<5` 不能被静默保存成普通数值 `5`；
- 缺失值使用 `null + missing_reason`，首版原因至少包括 `not_reported`、`not_applicable`、`not_available`、`redacted`、`parse_failed`；
- 受控术语同时保存代码、标签、词汇 URI 和词汇版本；未知术语保留原文，不能一律压成 `other`；
- schema 有独立版本号和迁移记录；新增可选字段可以向后兼容，改变字段语义必须升主版本并提供迁移脚本；
- DOI、IGSN、URL 和本地 ID 分开存储，不把不同标识符拼成一个不可解析的字符串。

### D-5. 查询、归档和检索视图

SQLite 只从规范化归档生成，建议建立：

- 主键索引：`dataset_id`、`sample_id`、`observation_id`、`method_id`；
- 常用索引：分析物、介质、数据集版本、采样时间、方法、许可状态、IGSN；
- 组合索引：`analyte + medium`、`source_id + dataset_version`、`sample_id + analyte`；
- 空间 R-Tree：用于 bbox 和附近样品查询；
- 全文检索：数据集标题、引用、地点描述、样品描述、岩性和方法说明。

首版提供四个查询视图：

1. `observation_search`：展开的测定长表，供 D2 按地区、介质、分析物、时间和方法筛选；
2. `sample_summary`：一个样品一行，展示位置、介质、已测参数和来源；
3. `source_coverage`：按来源、地区、介质、分析物和方法统计覆盖；
4. `provenance_trace`：从 `observation_id` 一步回到原文件、行列、版本和处理运行。

### D-6. 设计依据

- [EarthChem 数据模板](https://earthchem.org/ecl/templates)：把样品元数据、测定值、方法和数据来源分开，并用 Method Code 关联测定和方法；
- [EarthChem 推荐词汇](https://earthchem.org/ecl/vocabularies)：参数、单位、技术和矿物使用机器可读受控词汇；
- [DataCite IGSN 元数据建议](https://support.datacite.org/docs/igsn-id-metadata-recommendations)：样品持久标识、原始样品 ID、采样时间、位置、父子样关系和相关出版物；
- [OGC Observations, Measurements and Samples](https://www.ogc.org/standards/om/)：把样品、观测过程、被观测属性、方法和结果作为不同概念处理。

V2 只借鉴这些标准的核心概念，不直接实现完整 OGC/ISO 模型，也不把 DataCite 的通用 PID 元数据误当作完整的领域数据 schema。

## 八、工作流 E：是否够快，存成什么

### E-1. 快速的原则

- 能在服务端按地区、介质、元素过滤，就不先下载全库；
- 同一 URL、版本和请求参数命中验证缓存时，不重复联网；
- 大文件先顺序读取和列筛选，不一次全部载入内存；
- 对反复查询的数据建立本地索引；
- 网络速度属于外部条件，D1 主要减少重复请求和无效数据量；
- 记录首次获取、缓存获取、解析和筛选耗时，不能只说“应该很快”。

### E-2. 建议存储层次

```text
.cache/geochemical-atlas/                 # 仓库外，不提交 Git
  <source_id>/<dataset_version>/
    raw/                                  # 发布方原始文件，只读复用
    download-manifest.json                # URL、版本、时间、响应和 hash
    index.sqlite                          # 可选的本地查询索引

outputs/acquisition/<run_id>/             # 一次 D1 交付
  raw_observations.csv                    # 交给 D2 的来源原值长表
  sources.jsonl                           # 每条观测的来源证明
  run_manifest.json                       # 请求、来源、过滤、数量、耗时和输出 hash
  coverage.json                           # 已覆盖、部分覆盖和未覆盖项
```

格式选择：

- JSON：小型注册表、请求、运行清单和覆盖报告；
- JSONL：逐条来源证据，方便流式处理；
- CSV：D1 → D2 的通用交换格式，便于人工检查；
- SQLite：本地大数据查询和索引，不作为最终科学交付；
- Parquet：数据规模明显增大后再评估，V2 不为了格式引入不必要依赖；
- 完整第三方数据和本地 SQLite 均不进入 Git。

### E-3. D1 → D2 最低交付字段

### E-4. 建议性能目标（需审阅）

| 指标 | 建议目标 |
|---|---|
| 来源路由 | 本地目录选择在 1 秒内完成 |
| 重复获取 | 验证缓存存在时 0 次网络请求 |
| 缓存演示查询 | 10 万条以内在 10 秒内完成解析和筛选 |
| 内存 | 大文件使用流式处理，不以完整文件大小为最低内存要求 |
| 可复现 | 相同版本、请求和代码产生相同记录集合与输出 hash |
| 仓库体积 | 不提交完整第三方数据；全部 fixture 建议控制在 10 MB 内 |
| 失败行为 | 无网络、版本变化、字段变化和许可不清时给出明确状态 |

- [ ] 连续两轮信源发现复核无新增高相关来源，当前目录才可标记 `discovery_saturated`；
- [ ] 候选来源不能在未经准入的情况下自动进入生产；
- [ ] 每次获取记录实际接口、参数、版本、数量、耗时和 hash；
- [ ] 原始记录数与解析成功、明确拒绝和失败记录完全对账，无原因不明的静默丢失；
- [ ] 每个生产来源至少 30 条分层人工回看记录通过，且全量程序检查通过；
- [ ] 每条交付记录可追溯到来源文件和原始记录位置；
- [ ] 系统能区分 `covered`、`partial`、`uncovered` 和 `unknown`；

- [ ] 每个未覆盖单元至少有两个独立发现渠道的复核证据，否则只能标记 `unknown`；
- [ ] 聚合库、原始提供者和重复记录关系明确，不把同源数据误算为独立证据；

- [ ] 数据集、采样事件、样品、测定、方法和来源证据有独立稳定 ID 和明确关系；
- [ ] 同一样品的多个元素、多个方法、重复测定和父子样关系可以无歧义表达；

## 十二、主要风险

| 风险 | 可能误区 | 应对 |
|---|---|---|
| 把来源数量当作全面 | 接了很多重复来源，全球空白仍然存在 | 以覆盖矩阵和缺口收益排序 |
| 把权威来源当作每条记录都可靠 | 忽略方法、单位和采样差异 | D1 来源准入与 D2 记录 QC 分开 |
| 为追求速度下载不完整数据 | 分页、大小或过滤发生静默截断 | 记录预期数量、实际数量和截断状态 |
| 为追求开放而忽略许可 | 数据能下载但不能再分发 | 许可作为硬准入条件 |
| 把 schema 做成不断加列的大宽表 | 样品、方法和来源信息重复，更新后互相矛盾 | 分层归档，一行一个测定的长表只作为交换视图 |
| 标准化覆盖原始事实 | 后续无法判断原库到底写了什么 | `*_raw` 不可覆盖，转换字段记录规则和版本 |
| 把空值都当成一种缺失 | 无法区分未报告、不适用、被隐藏和解析失败 | `null + missing_reason` 并统计各类缺失 |
| 受控词汇漂移 | 同一术语在不同时间映射不同 | 记录词汇 URI、版本、原词和映射状态 |
| 存储格式过早复杂化 | 引入 Parquet/数据库依赖但收益有限 | V2 先 CSV/JSONL，SQLite 只做本地索引 |
| 接口变化 | API 路由、字段或版本变化 | 审计、版本锁定、契约测试和显式降级 |
| “全球地图”被误解为全球都有数据 | 覆盖空白被地图样式掩盖 | coverage 输出进入最终报告和地图说明 |

## 十三、已确认的决定与保留边界

已确认的最高原则：信源覆盖与数据准确性优先于来源数量、下载速度和展示效果；质量门未通过时不扩大结论。

已确认的范围：岩石、土壤、沉积物和水体全部要做；候选目录尽可能纳入所有可发现的相关信源，优先级只安排接入顺序，不缩减范围。

以下实现选择按审阅稿建议执行；后续如需改变，再通过计划提交追踪：

1. **文献边界**：D1 负责 DOI、引用和公开补充数据定位；V2 不自动从 PDF/OCR 提取数值。
2. **来源状态**：使用 `approved / conditional / metadata_only / needs_human_review / rejected`，不给来源一个看似精确的总分。
3. **schema 结构**：采用“分层归档 + 一行一个测定的长表交换 + SQLite 派生索引”，不长期维护一张大宽表。
4. **字段优先级**：P0 必须或说明缺失、P1 强烈建议、P2 专业扩展；首版先冻结 P0/P1，不强求所有来源填满 P2。
5. **存储选择**：使用 JSON + JSONL + CSV 作为交付格式，SQLite 只作为本地加速索引，暂不引入 Parquet。
6. **性能目标**：首版采用“缓存查询 10 万条以内 10 秒、缓存命中 0 次联网、fixture 总量不超过 10 MB”的目标。

## 十四、审阅后的执行方式

审阅通过后：

1. 根据审阅意见修改本文件并标记为 `已批准`；
2. 从最新 `main` 创建 `d1/source-system-v2`；
3. 每个里程碑单独提交，计划状态和验证记录同提交更新；
4. 涉及 D1 → D2 字段或 D3 运行接口时，在实现前先冻结契约；
5. V2-M4 先提交 data schema 和字段映射供审阅，冻结后再实现查询索引和新适配器；
6. V2-M3 完成后，再提交新数据源选择建议供审阅；
7. 未经审阅不扩大到 PDF 数值抽取、受限来源或大规模新数据源接入。
